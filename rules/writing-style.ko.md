# 문체 규칙

파일 종류별 문체는 `.wb/config.json` 의 `style.map` 이 정한다. 아래는 문체별 규칙이다.

## haeyo
대상: 화면 문구, 인앱 매뉴얼, 도움말, 안내 메시지.

- 해요체로 쓴다. 「저장해요」「선택하세요」처럼 짧은 존댓말이다.
- 한 화면에는 한 가지 주제만 둔다. 주인공이 되는 동작이나 값을 앞에 둔다.
- 제목은 평서문이나 명사구로 쓴다. 「~할까요?」 같은 질문형 제목은 쓰지 않는다.
- 설명을 덧붙여 꾸미지 않는다. 버튼 이름과 안내는 동작을 그대로 말한다.
- 줄표(―, --)로 문장을 이어 붙이지 않는다. 문장을 나눈다.
- 약어와 개발자 용어는 쓰지 않는다. 프로젝트 용어 사전이 있으면 그 낱말을 따른다.
- 문구 때문에 AI가 쓴 느낌이 나면 안 된다. 「쉽고 빠르게」「강력한」 같은 말은 쓰지 않는다.

## report
대상: 개발 문서, 보고서, 인증 서류, 배포 문서.

- 보고서체(「~한다」「~이다」)로 쓴다.
- 현황이나 문제를 먼저 쓰고, 적용 방안, 주요 내용, 영향 순으로 쓴다.
- 한 문장에는 한 가지 사실만 쓴다.
- 작업 과정을 설명하지 않는다. 「분석해 보겠습니다」「수정했습니다」 같은 문장을 쓰지 않는다.
- 근거 없는 평가(효율적, 안정적, 성능이 뛰어남)는 수치나 사실로 바꾸거나 뺀다.
- 개발자 은어는 업무 용어로 바꾼다. 과장과 비유(두뇌, 엔진, 강력한)는 쓰지 않는다.
- 확인하지 못한 내용은 「미확인」으로 표시하고 추측으로 채우지 않는다.

## plain
대상: 위 두 가지에 해당하지 않는 파일.

- 짧은 문장으로 쓴다. 기존 파일의 문체와 용어를 따른다.
- 이모지와 장식 표현을 쓰지 않는다.
