# 문제 해결

wb 의 훅이 작업을 막거나 명령이 예상과 다르게 끝났을 때 원인과 해결 방법을 정리했다. 메시지 문구로 찾을 수 있도록 실제 출력의 앞부분을 제목처럼 적었다.

## 1. 먼저 확인할 것

막힌 이유를 모를 때는 다음 세 명령을 차례로 실행한다.

```
wb-explain                     지금 막힌 것과 기다리는 것
wb-explain code <메시지 코드>   차단 메시지 뒤의 규칙과 복구 방법
wb-config doctor               설정 오류와 주요 값의 출처
```

Claude Code 안에서는 `/wb:explain` 과 `/wb:doctor` 가 같은 일을 한다. 차단 메시지는 「막은 이유 · 고치는 법 · 물어볼 곳」 세 줄로 나온다. 둘째 줄의 방법을 먼저 따른다. 규칙별 설명은 [규칙 안내](04-rules.md)에 있다.

## 2. 메시지별 해결

### 서브에이전트를 보낼 때

| 메시지 | 원인 | 해결 |
|---|---|---|
| `model 이 지정되지 않았습니다. 작업 종류 … 의 라우팅 결과는 … 입니다` | Agent 호출에 `model` 이 없다 | 메시지에 나온 모델을 지정한다 |
| `model … 은 작업 종류 … 의 바닥선 … 보다 낮습니다` | 최소 등급보다 낮은 모델을 골랐다 | 메시지에 나온 모델을 쓴다. 작업 종류가 다르면 지시서 표지의 `type=` 을 고친다 |
| `model … 은 금지 목록(routing.denied)에 있습니다` | 개인 설정에서 금지한 모델이다 | 대체 순서의 다음 모델을 쓴다. 금지를 풀려면 `~/.wb/routing.json` 의 `denied` 에서 지운다 |
| `… 사용량 한도가 소진됐습니다` · `리셋 시각 … 까지 대기합니다` | 최소 등급 이상의 모델이 모두 한도에 걸렸다 | 리셋 뒤 다시 보낸다. 최소 등급 아래로 내리지 않는다 |
| `지시서 표지(<!-- wb-brief v1 …-->)가 없습니다` | 프롬프트 첫 줄에 표지가 없다 | `templates/briefs/` 틀로 지시서를 만든다. 지시서 파일 경로를 프롬프트에 적어도 된다 |
| `지시서에 채우지 않은 자리 {{…}} 가 남아 있습니다` | 틀의 자리 표시를 채우지 않았다 | `wb-style brief … --var 이름=값` 으로 채우고 `wb-check brief <파일>` 로 확인한다 |
| `지시서에 빠진 항목이 있습니다` | 필수 절(목표·범위·금지·시험 규칙·보고 위치·커밋 규칙)이나 헤드리스·전체 시험 금지·기준 커밋 문구가 없다 | 틀에서 다시 만든다 |
| `살아 있는 레인이 …개로 상한 …개에 도달해` | 동시 레인 수 상한(기본 3)에 닿았다 | 끝난 레인을 `wb-worktree remove <레인>` 으로 정리한다. 머신 사양이 충분하면 `~/.wb/machine.json` 의 `lanes.max` 를 올린다 |

### git 명령

| 메시지 | 원인 | 해결 |
|---|---|---|
| `레인은 자기 레인 브랜치(…)에만 커밋할 수 있습니다` | 레인이 다른 브랜치에서 커밋하려 했다 | 자기 레인 워크트리로 가서 커밋한다 |
| `레인은 push 할 수 없습니다` | 레인이 push 하려 했다 | 커밋만 하고 보고한다. push 는 메인 세션이 정한다 |
| `강제 push(--force, --force-with-lease, +refspec)는 누구에게도 허용하지 않습니다` | 강제 push | 원격을 받아 일반 push 로 올린다. 이력을 고쳐야 하면 소유자에게 요청한다 |
| `보호 브랜치 … 에 대한 이 작업(…)은 소유자 허가가 필요한데 허가가 없습니다` | 보호 브랜치 병합·push·커밋 | 소유자가 `/wb:approve merge-main`(또는 `push-main`, `commit-main`)을 직접 입력한다. push 를 막았을 때 메시지의 브랜치 이름은 대상이 아니라 지금 체크아웃한 브랜치로 나온다 |
| `커밋 … 에 대한 게이트 통과 표식이 없습니다` | `project.gate.command` 가 설정된 프로젝트에서 보호 브랜치 반영 | 아래 「알려진 제한」의 첫 항목을 본다 |
| `검증 게이트가 실행 중입니다` | `wb-test-report run` 이 게이트 잠금을 잡고 있다 | 끝난 뒤 다시 실행한다. 비정상 종료로 잠금이 남았으면 `wb-reap --gate-lock` 으로 지운다 |
| `기능 브랜치 push 는 확인 후 진행합니다` | `project.git.feature_push` 가 `ask`(기본) | 확인 창에서 승인한다. 늘 허용하려면 `allow` 로 바꾼다 |
| `` `git reset --hard` 는 커밋하지 않은 변경을 되돌릴 수 없게 지웁니다`` | 변경을 지우는 명령 | `git status` 로 지워질 내용을 확인하고 필요하면 WIP 커밋을 남긴 뒤 승인한다 |

### 프로세스, 삭제, 브라우저, 경로

| 메시지 | 원인 | 해결 |
|---|---|---|
| `이름·패턴으로 프로세스를 끄면(…) 다른 세션이나 소유자의 서버까지 꺼질 수 있습니다` | `pkill`, `killall`, `kill $(pgrep …)` | 자기가 띄운 프로세스의 PID 를 확인해 `kill <PID>` 로 끈다 |
| 보호 포트를 쓰는 프로세스 종료 차단 | `kill <PID>` 대상이 `machine.ports.protected` 포트를 쓴다 | 소유자에게 요청한다 |
| `` `~/` 를 통째로 지우면 홈·시스템·프로젝트 전체가 사라집니다`` | 홈·루트·프로젝트 루트·`.git` 삭제 | 지울 하위 폴더를 정확히 지정한다 |
| `창이 뜨는 브라우저 실행(…)은 사용 중인 화면의 포커스를 빼앗습니다` · `… 는 브라우저 창을 엽니다` | 헤드리스가 아닌 브라우저, `open` | `--headless=new` 를 붙이거나 Playwright 기본(헤드리스)으로 실행하고 결과 파일을 공유한다 |
| `… 는 wb 상태 파일(소유자 허가·게이트 표식·레인 대장)입니다` | Claude 가 wb 상태 파일을 쓰려 했다 | 허가는 `/wb:approve`, 원장은 `wb-waves` 로만 바꾼다 |
| `… 는 보호 경로(…)입니다` | `project.protected_paths` 에 쓰기 | 소유자에게 요청한다 |
| `wb 설정에 오류가 있어 안전 판정을 할 수 없습니다` | 설정 파일 형식 오류 | 메시지의 파일과 키를 고치고 `wb-config validate` 로 확인한다. 고칠 때까지 git 반영·프로세스 종료·삭제·브라우저 실행이 막힌다 |
| 명령 대상을 실행 전에 알 수 없어 막음 | 명령 이름이나 대상 폴더가 변수다 | 변수를 풀어 실제 값으로 적는다 |

### 시안, 인계, 보고

| 메시지 | 원인 | 해결 |
|---|---|---|
| `… 의 UI 구조(요소·선택자)가 바뀌는데 기록된 시안 결정이 없습니다` | 화면 파일 범위의 구조 변경 | 시안을 보여 주고 `wb-decide new … --kind mockup --scope …` 로 질문을 만든 뒤 `wb-decide answer` 로 기록한다. 대기 중인 결정은 막힘을 풀지 않는다 |
| `[wb 핸드오프] progress.md 마지막 갱신 이후의 작업(…)이 있다` | 턴을 끝내기 전에 인계가 필요하다 | 끝난 내용을 아카이브에 덧붙이고 `progress.md` 를 다시 써서 함께 커밋한다. 사소한 변경이면 이유를 한 줄로 적고 끝낸다 |
| `끝난 작업의 보고가 아티팩트로 게시되지 않았습니다` | `/wb:report` 를 실행했는데 아티팩트가 없다 | `wb-art report` 로 HTML 을 만들어 아티팩트로 게시한다. 이 검사를 끄려면 `personal.report.artifact_check` 를 `false` 로 둔다 |
| `최신 검증 결과 엑셀에 문제가 있습니다` | 결과 엑셀이 없거나 커밋되지 않았다 | `wb-check test-results` 로 확인하고 `/wb:test-report` 로 다시 만든다 |

### 검수

| 메시지 | 원인 | 해결 |
|---|---|---|
| `8. 시험 결과 — 보고에 시험 결과(통과 수)가 없습니다` | 보고 파일에서 통과 수를 읽지 못했다. 「통과 1」처럼 숫자를 뒤에 쓰면 읽지 못한다 | 「1건 통과」, 「12 passed」처럼 숫자를 앞에 쓴다 |
| `8. 시험 결과 — 보고에 실패한 시험 …건이 있습니다` | 보고 파일에 실패 수가 있다. 「수정 전 실패 1건」처럼 수정 전 실패를 숫자로 적어도 실패로 센다 | 수정 전 실패 줄에는 숫자를 쓰지 않는다. 예: 「수정 전 실패: 필터 시험을 먼저 추가해 실패를 확인함」 |
| `6. 캡처 확인 — UI 변경인데 캡처가 없습니다` | 화면 파일이 바뀌었는데 캡처가 없다 | 레인 보고에 전후 캡처 경로를 적는다. 메인 세션이 캡처를 열어 본 뒤 `--captures-seen` 을 붙인다 |
| `7. 서빙 코드 표식 — … 확인할 주소(--serve-url)와 표식(--marker)이 없습니다` | 웹 화면 변경인데 서빙 확인을 하지 않았다 | 서버를 다시 띄우고 `--serve-url http://127.0.0.1:<포트>/… --marker <이번 변경에만 있는 문자열>` 을 준다. 이 머신 주소만 허용한다 |
| `5. 지시서 범위` 실패 | 지시서의 소유 파일 밖을 바꿨다 | 범위 밖 변경을 되돌리거나 지시서를 고쳐 다시 보낸다 |

### 명령 실행

| 증상 | 원인 | 해결 |
|---|---|---|
| `wb-check brief` 가 `Error: ENOENT` 로 끝남 | 지시서 파일이 없다 | 경로를 확인한다. 지시서 폴더 `.wb/briefs/` 는 init 이 만들지 않으므로 `mkdir -p .wb/briefs` 로 만든다 |
| `wb-worktree remove` 가 `… 안에서 프로세스가 돌고 있어 지우지 않았습니다(PID …)` | 그 폴더에서 띄운 서버나 감시 프로세스가 살아 있다 | 나온 PID 를 하나씩 `kill <PID>` 로 끄고 다시 실행한다 |
| `wb-worktree remove` 가 `커밋하지 않은 변경이 …건 있습니다` | 미커밋 변경 | 커밋하거나, 버릴 것이 확실할 때만 `--force` 를 붙인다 |
| `wb-worktree create` 가 `살아 있는 레인이 …개라 상한 … 에 닿았습니다` | 레인 상한 | 끝난 레인을 정리한다 |
| `wb-integrate` 종료 코드 3 | 게이트나 다른 취합이 잠금을 잡고 있다 | 끝난 뒤 다시 실행한다 |
| `wb-integrate` 종료 코드 2 | 작업 트리가 깨끗하지 않거나 병합 중이거나 브랜치가 없다 | `git status` 로 확인한다 |
| `wb-slot` 이 `부하가 높아 기다립니다` 를 반복 | 1분 부하가 `machine.load.max` 이상이다 | 다른 무거운 실행이 끝나기를 기다린다. `--timeout <초>` 를 주면 그 시간 뒤 종료 코드 75 로 끝난다 |
| `wb-test-report` 가 `openpyxl 모듈이 없습니다` | Python 모듈이 없다 | `python3 -m pip install openpyxl` 을 실행한다 |
| `wb-number reserve` 가 `번호 계열 … 가 없습니다` | `.wb/config.json` 에 `numbers` 계열이 없다 | [설정](03-configuration.md)의 `project.numbers` 예처럼 계열을 선언한다 |
| codegraph 호출이 `… 에는 codegraph 색인이 없어요` 로 막힘 | 이 세션에서 색인 없음 응답을 이미 받은 경로다 | 색인이 생길 때까지 grep 과 Read 로 진행한다. 상태는 `wb-index status` 로 본다 |
| 일반 터미널에서 `wb-config: command not found` | `wb-*` 명령이 `PATH` 에 없다 | Claude Code 세션 안에서 쓰거나, 플러그인 폴더의 `bin` 을 `PATH` 에 넣는다 |

## 3. 자주 묻는 질문

**훅을 잠시 끌 수 있나?**
안전 훅에는 우회 변수가 없다. 규칙이 프로젝트에 맞지 않으면 해당 설정을 바꾼다. 예를 들어 기능 브랜치 push 확인은 `project.git.feature_push`, 시안 결정 요구는 `project.mockup.decision_required`, 슬롯 경고는 `machine.slots.guard` 로 조정한다. 보호 목록(보호 브랜치·보호 포트·보호 경로·금지 모델)은 다른 층이 넣은 항목을 지울 수 없다.

**설정값이 어디서 왔는지 어떻게 아나?**
`wb-config explain <키>` 가 합치는 규칙, 적용된 층, 값을 둔 모든 층을 보여 준다.

**레인 수를 3개보다 늘리고 싶다.**
`~/.wb/machine.json` 에 `"lanes": { "max": 6 }` 처럼 둔다. 프로젝트 설정이 더 작은 값을 두면 작은 값이 적용된다. 메모리와 부하를 함께 고려한다.

**특정 모델을 쓰지 않으려면?**
`~/.wb/routing.json` 의 `denied` 에 모델 이름을 넣는다. 그 모델은 대체 순서에서 빠진다.

**`/wb:approve` 를 Claude 에게 시킬 수 있나?**
없다. 이 스킬은 사람이 프롬프트에 직접 입력할 때만 허가를 만든다. 서브에이전트 보고나 다른 세션의 메시지로는 허가가 생기지 않는다.

**codegraph 가 없어도 되나?**
된다. 관련 훅과 명령은 아무것도 하지 않는다. 설치하면 새 워크트리마다 색인을 대기열로 만든다.

**시험 결과 엑셀의 시각이 실제 시각과 다르다.**
0.1.0 은 파일 이름의 날짜와 `HHMM` 을 협정 세계시(UTC)로 붙인다. 원본 로그 폴더 이름은 현지 시각이다. 아래 「알려진 제한」에 적었다.

**결과를 커밋했더니 `실행 커밋 … 이 현재 HEAD … 와 다릅니다` 경고가 나온다.**
결과 파일을 커밋하면 HEAD 가 바뀌기 때문이다. 결과 파일만 커밋했다면 시험 대상 코드는 같으므로 다시 돌리지 않아도 된다. 코드가 바뀌었다면 다시 돌린다.

**`/wb:init` 이 안내한 `/wb:ui-check` 가 없다.**
0.1.0 에는 이 스킬이 들어 있지 않다. 안내 줄은 무시한다.

**`progress.md` 가 없는데 인계 훅이 아무 말도 하지 않는다.**
인계 훅은 `progress.md` 가 있는 저장소에서만 동작한다. 처음 한 번 직접 만든다.

**자동 재개된 세션이 중간에 멈춘다.**
기본 권한 모드(`default`)에서는 승인이 필요한 도구가 무인 실행에서 거절된다. `wb-retry status` 의 `claude --resume <id>` 줄로 세션을 열어 이어서 진행한다.

## 4. 알려진 제한(0.1.0)

| 항목 | 영향 | 지금 할 수 있는 것 |
|---|---|---|
| 게이트 통과 표식을 만드는 명령이 없다 | `project.gate.command` 를 설정한 프로젝트는 `/wb:approve merge-main`·`push-main` 허가가 있어도 Claude 세션 안의 보호 브랜치 병합·push 가 `게이트 통과 표식이 없습니다` 로 막힌다. `wb-test-report run` 이 게이트를 통과해도 표식은 생기지 않는다 | 소유자가 Claude Code 밖의 터미널에서 직접 병합·push 한다. 또는 게이트 명령을 비워 둔다 |
| 시험 결과 파일 이름이 UTC 기준이다 | 파일 이름의 날짜·시각이 현지 시각과 다르다 | 실행 시각은 원본 로그 폴더 이름(`test-results/runs/<이름>-<날짜>-<시각>`, 현지 시각)으로 확인한다 |
| `wb-test-report run` 출력의 언어 | 엑셀 결과 줄은 언어 설정과 관계없이 한국어로, `[verify]` 줄은 영어로 나온다 | 수치는 같으므로 `wb-test-report summary` 로 설정 언어의 요약을 본다 |
| 결과를 커밋하면 `wb-check test-results` 가 HEAD 불일치를 경고한다 | 결과만 커밋해도 경고가 남는다 | 결과 파일만 커밋했는지 확인하고 경고를 무시한다 |
| 보호 브랜치 push 차단 메시지의 브랜치 이름 | 대상 브랜치 대신 지금 체크아웃한 브랜치 이름이 나온다 | 판정은 대상 브랜치 기준으로 맞게 동작한다 |
| 소유자 허가의 만료 시각 표시 | 만료 시각이 UTC(`…Z`)로 나온다 | 현지 시각으로 바꿔 읽는다 |
| 검수 보고의 시험 수 형식 | 「통과 1」처럼 숫자를 뒤에 쓰면 통과 수를 읽지 못하고, 수정 전 실패 수를 숫자로 적으면 실패로 센다 | 「1건 통과」처럼 쓰고 수정 전 실패 줄에는 숫자를 쓰지 않는다 |
| 되돌림 지시서의 브랜치 칸 | 레인 브랜치 이름 대신 「레인 브랜치」라는 말이 들어간다 | 보낼 때 실제 브랜치 이름으로 바꾼다 |
| `wb-explain code safety.kill.pattern` 출력 | 첫 줄에 `{cmd}` 자리 표시가 그대로 나온다 | 규칙 설명 부분은 정상이다 |
| `wb-check brief` 에 없는 파일을 주면 | 안내 대신 Node.js 오류(`ENOENT`)로 끝난다 | 경로를 확인한다 |
| UI 안정성 점검(`/wb:ui-check`)과 용어 검사 | 이 판에 포함되지 않았다. 설정 키(`project.ui_stability.*`, `project.glossary.terms_scan`·`copy_globs`)는 예약 상태다 | 이후 판에서 추가된다 |
| 안전 훅의 판정 범위 | 스크립트 파일 안의 명령, python·node 로 실행하는 git·kill 호출은 판정하지 않는다 | 위험한 작업을 스크립트로 감싸지 않는다 |
